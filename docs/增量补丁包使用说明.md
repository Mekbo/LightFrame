# 光影工坊 LightFrame · 增量补丁包使用说明

## 一、发版策略（先看这个）

从 **v1.0.0** 起，仓库采用「**一个完整首发包 + 后续增量补丁包**」的发布方式：

- **v1.0.0 完整安装包**（`LightFrame_Setup_v1.0.exe`，约 100 MB）：唯一的首发基线包，已内置公司局域网证书兼容修复。**全新安装的用户只需装这一次**，以后不用再下载完整包。
- **后续每个新版本**：只发布一个很小的**增量补丁包**（通常只有几 KB ~ 几百 KB）+ 本说明。已安装 v1.0.0 的用户下载补丁、按下面步骤替换文件即可完成升级，无需重装、不会丢失任何配置和素材。

> 简单说：**第一次装完整包，以后每次升级只打小补丁。**

## 二、补丁包里有什么

补丁包是一个 zip，解压后通常是这样的结构（路径相对「安装目录」）：

```
补丁包_vX.Y.Z.zip
└── app\
    └── backend\
        └── services\
            └── app_update.py      ← 要替换的文件（示例）
└── 本版本更新说明.txt              ← 这次改了什么、要注意什么
```

**关键原则**：补丁包里的文件夹结构，就是相对于「安装目录」的真实路径。把补丁包解压后，按同样的相对路径，把文件覆盖到安装目录对应位置即可。

## 三、安装目录在哪

默认安装位置是：

```
C:\Program Files\光影工坊\
```

（如果安装时改过路径，以你当时选的位置为准。）下面几个路径会反复用到：

| 用途 | 路径 |
|---|---|
| 后端服务源码目录 | `安装目录\app\backend\services\` |
| 前端页面 | `安装目录\app\static\` |
| 启动器 / 管理器 | `安装目录\光影工坊.exe` |
| 配置文件 | `安装目录\app\config\` |

> 找不到安装目录？双击「光影工坊.exe」打开「启动设置 / 管理器」页面，里面显示了安装路径。

## 四、升级步骤（务必按顺序做）

### 第 1 步：停止服务
双击「光影工坊.exe」打开管理器 → 点「**停止**」。

### 第 2 步：结束残留进程（最关键，别跳过）
后端服务是不热加载代码的。只点「停止」有时旧进程还驻留在内存里，导致"替换了文件却没生效"。

- 按 `Ctrl + Shift + Esc` 打开任务管理器 → 「详细信息」
- 找到所有 **`python.exe`** 进程 → 全部右键「结束任务」

> 服务器版（如 Windows Server 2019）如果服务是开机自启的后台进程，这一步尤其重要。

### 第 3 步：备份（养成习惯）
把要被替换的原文件复制一份，例如把
`安装目录\app\backend\services\app_update.py`
复制成 `app_update.py.bak`。出问题可以直接改回来。

### 第 4 步：替换文件
把补丁包解压，按相对路径把文件复制到安装目录对应位置，选择**覆盖**。

例如补丁包里的 `app\backend\services\app_update.py`，就覆盖到
`安装目录\app\backend\services\app_update.py`。

### 第 5 步：重启服务
双击「光影工坊.exe」→ 点「**启动**」（或「重启」）。

### 第 6 步：验证升级成功
1. 浏览器打开应用，进入「关于应用 → 系统更新」。
2. 看「当前版本」是否已变成补丁的版本号（如 v1.0.1）。
3. 点「立即检查更新」，状态应显示「**已是最新版本**」。

看到新版本号，就说明升级成功了。

## 五、常见问题

**Q：替换了文件，版本号还是没变？**
A：99% 是第 2 步没做——旧进程还在内存里跑着老代码。回到第 2 步，结束所有 `python.exe`，再重启。

**Q：怎么确认新代码真的加载了？**
A：更新检查的错误信息里带一个构建标记（如 `[v1.0.0-certfix-20261116]`）。有标记 = 新代码已加载；没有 = 服务还没重启。

**Q：升级会丢配置 / 素材 / 任务记录吗？**
A：不会。补丁只替换程序文件，`config\`（配置/账号）、`space\`（素材空间）、产物目录都不动。但保险起见仍建议升级前备份 `config\` 目录。

**Q：装补丁时提示"文件正在使用，无法覆盖"？**
A：说明服务还在运行。回到第 1、2 步，彻底停服并结束 `python.exe` 后再替换。

## 六、给维护者：如何制作增量补丁包

1. 改完代码后，**只把本次变动的程序文件**按安装目录的相对路径放进一个临时目录（如 `app\backend\services\xxx.py`）。
   - 不要放 `config\`、`space\`、`output\` 等用户数据目录。
   - 不要放整个运行时（`runtime\`）和 100 MB 的 ffmpeg。
2. 附一份「本版本更新说明.txt」，写清改了什么、是否需要重启、注意事项。
3. 压缩成 zip，**文件名用 ASCII**（如 `LightFrame_Patch_v1.0.1.zip`）——中文名在 GitHub 上传会乱码。
4. 在 GitHub 新建 Release（tag 用新版本号），上传该 zip 作为附件，Release 说明里引用本文件并写清升级步骤。
5. 同步版本号真值：
   - `backend/services/app_update.py` 的 `APP_VERSION`、`RELEASE_DATE`、`CHANGELOG`
   - 根目录 `VERSION` 文件
   - 两者必须一致，否则应用内显示的版本会对不上。

> 发版一致性清单、证书库差异等更多经验，见 `docs/光影工坊_项目复盘经验_v1.md`。
