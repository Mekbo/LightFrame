# 光影工坊 · 图片批处理模块开发经验沉淀

> 适用：FastAPI + 静态前端 的图片/视频批处理工具；可复用于同类「多文件上传 → 后台任务 → 进度查询」型产品。
> 整理日期：2026-11-11

## 一、架构选型（一次定对，省后面十次返工）

| 维度 | 决策 | 经验 |
|---|---|---|
| 后端 | FastAPI + Uvicorn（端口 2026） | 轻量、异步、自带路由，适合「接收多文件 → 后台跑任务 → 轮询进度」模型 |
| 前端 | 单页 `static/index.html`（原生 HTML/JS，直读磁盘） | **改 HTML/JS 无需重启后端**，调试循环极快；但状态管理需自己来 |
| 配置 | 全局 `config/config.json` + 用户级 `config/users/{uid}.json`，`deep_merge` 继承 | 两级配置既能给默认值又能按用户隔离；**全局值会作为 base 被继承，改全局要小心影响所有人** |
| 运行环境 | 用 WorkBuddy 自带 python 完整路径启动 | 后台 shell 用相对/系统 python 会 `exit 127`；**永远用完整路径**，前端改动不用重启 |

## 二、关键技术决策与踩坑

### 1. 输出路径跨机器兼容 —— `Path.home()` 而非硬编码
- 图片 `OutPut_Image`、视频 `OutPut_Video`，根目录用 `Path.home()/"Documents"/"LightFrame"`。
- 换电脑 / 换登录账号路径自动生效，代码里绝不拼用户名。

### 2. 文字模板「尺寸相对渲染」—— 归一化坐标 + ratio
- 字体大小、描边、阴影一律存**比例**（如 `size_ratio`=图片高度×比例，下限 1px；`width<=0` 即禁用），不存绝对 px。
- 验证：9:16 在 900×1600≈96px、1080×1920≈115px，占比都是 6%，**同规格不同尺寸效果一致**。这是模板能跨图尺寸复用的核心。
- 踩坑：早期直接存 px + `max(1,…)`，同模板在不同图尺寸下字大小漂移；改 ratio 后根治。

### 3. 字体自动加载
- 扫描 `backend/fonts/` + 系统字体目录，默认「思源黑体」，未装回退 `msyh.ttc`。丢字体进 `fonts/` 即自动升级，零改码。

### 4. 多行文案「一行一图 + 去重 + 循环」
- 后端 `_split_text_lines()`：按行拆 → 去空白 → **去重保序**。
- 处理循环按 `图序号 % 去重后行数` 取文案：行少自动循环，行多只用前 N 行（「以图片数决定调用文案数」）。
- 用 `text_override` 参数逐图传单行文案，**不污染原始 cfg**，保证暂停/恢复仍正确。
- 前端文案存 `localStorage`（刷新不丢），仅「清空文案」按钮能清；预览只取首行。

### 5. 缩放开关刷新回弹 —— 「手动切换不自动保存」
- 根因：只有点「保存设置」才写盘，刷新后 `loadConfig` 读回服务端旧值；而全局 `config.json` 里 `resize=true` 被继承。
- 修复：给 5 个功能开关加 `onchange="autoSaveConfig()"`（防抖 400ms 静默保存），开关状态即时落盘到用户配置，覆盖全局默认。
- **经验**：任何「用户期望刷新后保持」的 UI 状态，要么自动保存，要么存 localStorage，不能只靠「保存设置」按钮。

### 6. 视图与危险操作的权限收窄
- 「删除全部」→「批量删除」（按勾选，tooltip 提示谨慎）；「查看」从「缩略图+下载」简化为 `os.startfile` 直接开目录。
- 经验：面向运营人员的功能，危险动作要默认收窄、给二次确认和 tooltip。

## 三、可复用的工程约定

1. **尺寸相对化**：所有「位置/字号/描边/阴影」走归一化坐标 + ratio，模板才能跨尺寸通用。
2. **preview 不入库**：模板预览底图只用于实时预览，保存时剔除 `preview_image` 字段，避免污染数据。
3. **per-tool 独立 `enabled` 开关**：配置用嵌套 `{convert:{enabled}, crop:{enabled}, resize:{enabled}, text:{enabled}}`，管线按开关顺序执行，暂停/恢复不丢状态。
4. **状态落盘两路**：服务端配置（长期、跨设备）用 `saveConfig`；纯前端临时态（如文案草稿）用 `localStorage`（刷新不丢，不污染服务端）。
5. **验证用合法 Windows 路径**：测试图生成到 `C:/Users/…/AppData/Local/Temp/`，不要写 `/tmp`（Windows 上 Python 解析失败）。

## 四、验证方法论（每次改动都走这套）

```
改代码 → node --check 校验内联 JS → 完整 python 路径重启后端 →
curl 端到端接口测试 → 像素级/字段级比对验证 → 清理测试产物 → 写 memory 日志
```

- **像素级验证要同字体才权威**：两端都用服务端同一字体，只比对底部文案区裁剪，避免源图标签干扰。
- **区分「去重」必须用具区分用例**：用 `甲,甲,甲,乙` → 期望 `甲,乙,甲,乙`，才能验证去重+循环，而非 `A,B,C,A`（无法区分去重与否）。
- 静态前端改动跳过「重启」，直接 curl 页面确认新代码已服务。
