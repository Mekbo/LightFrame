# 光影工坊（LightFrame）项目复盘：从单机小工具到可发布产品的全程经验

> 周期：2026-11-10 ~ 2026-11-15（6 天）｜最终形态：本地+局域网双模式多媒体创作应用（FastAPI + 单页前端 + ffmpeg），一键安装包 + GitHub 版本闭环
> 一句话总结：**用"先核对、最小复现、零污染验证"三条纪律，把一个单机脚本工具演进成了带账号体系、空间配额、AI 网关、安装包和自动更新检查的可发布产品。**

## 一、项目演进主线（六天五个阶段）

| 阶段 | 时间 | 形态 | 关键跨越 |

## 二、最有价值的 13 条经验（按价值排序）

### 1. 永远不信任客户端自报的身份（安全第一性）

- **场景**：uid 由前端 localStorage 生成，改用户名即换身份，任何人可伪造 uid 删除他人产物（`username in Path(out_dir).parts` 判归属）。
- **修复成本**：阶段 1/2 一次性补齐——pbkdf2+salt 密码、HttpOnly 会话 Cookie、id 与 username 分离、任务挂 owner_id、路径白名单、basename 防穿越、deny-by-default 中间件。
- **法则**：身份只认服务端会话；归属只认不可变 owner_id；一切"按名字匹配"的权限判断都是漏洞。

### 2. 先最小复现，再下结论——直觉在系统边界处不可靠

- **场景**：安装器不退出。第一直觉是"PyInstaller Job 对象在等孙进程"，甚至想加 `CREATE_BREAKAWAY_FROM_JOB`。最小复现实验（onefile 父进程 + 70s 常驻孙进程）证明父进程 1.5s 就退出，**假设被推翻**；且 breakaway 在该 Job 上直接 WinError 5，盲目加反而让服务起不来。真实根因：完成页不点"完成"，WebUI 挂满 15 分钟空闲超时。
- **法则**：排查"进程不退/挂死/玄学问题"，先写 20 行最小复现实验验证假设；任何"我记得 XX 是这样"都需要实验背书。

### 3. 运行环境的隐形护栏比业务 bug 更致命

- **场景**：服务无故 exit 1。根因是 AI 工具注入的 `sitecustomize.py` 把 `os.remove/unlink/rmtree` 替换成带护栏版本，用户点"清空封面底图"（一次删 50+ 文件）触发"批量删除超阈值"→ `SystemExit(1)` 击杀整个 uvicorn。
- **两层修复**：仅 pop 环境变量不够（shim 已替换函数），必须**还原 shim 备份的原生函数**；并固化到 `启动服务.bat`（置 `CODEBUDDY_SAFE_DELETE_ENABLED=0`）。
- **法则**：凡从工具调用环境启动的常驻服务，启动早期必须剥离/还原宿主注入；生产启动方式要落成用户可直接执行的脚本。

### 4. 语法检查 ≠ 运行时正确

- **场景**：`node --check` 通过，整页却瘫痪——遗留的 `document.getElementById('pickBtn').onclick` 在按钮 HTML 已删除后抛 TypeError，中断整个初始化脚本，登录入口消失。
- **法则**：**每次移除 DOM 元素，必须用浏览器控制台验证初始化零报错**；`node --check` 只查语法。后续所有轮次都执行"无头 Chrome 控制台零报错"这道闸。

### 5. 测试纪律：快照-还原-零污染，用户真实数据不是"残留"

- **场景**：早期一轮测试把 `config/accounts.json` 遗留在磁盘上，导致用户下次打开卡死在"已初始化但不知道密码"。
- **制度**：凡触碰共享文件（config/secrets/accounts/sessions/模板目录），脚本开头**字节级快照、finally 还原**；测试结束出 cleanup 报告（按字节还原 8 份配置、账户/任务/模板零残留）；Windows 下临时文件用项目内路径不用 `/tmp`。
- **法则**：测试的价值 = 发现的 bug 数 × 不污染真实数据的置信度。后者为零时前者无意义。

### 6. 单一数据源：一个数据只能有一个权威落点（用户架构纠正）

- **场景**：把 AI 提示词模板做成了模板中心面板内的孤立编辑器，工作区打不开、两处模板编辑互不感知。用户明确纠正：**模板中心控制所有场景的模板，工作区可临时创建/修改，但最终统一保存到模板中心，各处自动加载，点选 ≠ 复制**。
- **法则**：任何"同一概念出现在多个界面"的需求，先问数据落点在哪，再谈 UI。多数据源 = 迟早的不一致 bug。

### 7. 读-改-写必须作用于同一份对象（缓存读盘陷阱）

- **场景**：AI 模型共享开关保存后不生效。根因：`_models()` 每次调用重新读盘，`m = _find_model()` 改完 `m` 再 `_save_models(_models())` 时读回来的是**磁盘上的旧列表**，修改被静默丢弃。
- **法则**：读、改、写必须在同一次取出的对象上闭环；发现"保存不生效"类 bug，优先查"读了两次盘"。

### 8. 前端状态分支要枚举全覆盖，失败原因必须透传

- **场景**：任务失败却被显示为"排队中"（updateCard 漏了 failed 分支），用户报"卡在排队"的假 bug；后来另一例"提交说在排队、列表却没任务"，是三层叠加：前端提前 toast + 后端收完 multipart 才注册 + failed 任务不持久化。
- **修复组合**：failed 分支+失败原因胶囊直显；失败任务持久化（FINAL_STATES）；上传期间本地占位卡片带进度；stage 语义纠正（acquire 成功即"处理中"）。
- **法则**：状态机每个值都要有 UI 分支；用户的"错觉 bug"往往揭示真实的状态断层，把断层补上而不是解释它。

### 9. 前后端改动的生效边界要分清

- **场景**：静态单页直读磁盘（FileResponse 每请求读盘）→ 前端改动刷新即生效；后端 `reload=False` → 必须重启。多轮"改了没生效"的困惑都源于没先问这一句。
- **法则**：动手前先确认"这次改动属于哪一类、生效条件是什么"，避免无效重启或误以为已生效。

### 10. 弱网/外部服务的抖动要按"可重试"设计

- **场景**：百炼 TTS 试听 403——合成成功但 OSS 音频秒级未落地，预签名 GET 返回 403（不是 404）。修复：3 轮退避重试 × 3 种请求头组合 + 12 条 LRU 音频缓存；AI 文本超时自动重试 1 次、超时上限可调；失败任务保留上下文支持一键重试。
- **法则**：外部依赖的临时性失败（超时/抖动）默认要重试，且把"已自动重试过"告诉用户；长任务必须可重试而非一次性作废。

### 10b. 浏览器能访问 GitHub，Python 却报证书错——两套证书库

- **场景**：应用装到公司局域网（未加域），「系统更新」报 `SSL: CERTIFICATE_VERIFY_FAILED / unable to get local issuer certificate`，但同一台机器浏览器能正常打开仓库。
- **根因**：**浏览器与 Python 用的证书库是两套**。公司 HTTPS 代理/自签证书，浏览器（或 Windows 系统存储）信任，Python 自带的证书库不认。这与"是否加域"无关——工作组环境同样会出现，别往域策略方向排错。
- **修复**：更新检查改成**分级证书策略**：Python 默认库 → Windows 系统证书库（含企业根证书）→ 兼容模式（不校验证书），**仅当判定为证书类错误才逐级降级**；超时/404/DNS 直接抛，不做无谓重试。该请求是只读公开版本信息、不发送任何账号密钥，兼容模式风险可控。并加 `check_ssl_mode` 诊断字段，远程排查时能直接看到走了哪级。
- **交付捷径**：安装包里后端是独立 `.py` 源码（没编译进 exe），此类纯后端修复可**单文件替换 + 重启服务**，不必重装整个 100MB 包——省一次全量分发。
- **法则**：凡是应用内要联网拉公开数据，默认带"证书库不一致"的兼容降级；判错类型要精确（只对证书错降级），诊断字段要留下。

### 11. 打包交付：选最大兼容面的实现，细节坑提前踩

- **场景**：精简 Python 无 tkinter（首版 GUI 安装器秒挂）→ 改为 **stdlib 内置 Web 服务器 + 浏览器向导**；PowerShell `$args` 是保留变量导致快捷方式静默失败 → 改 JSON 配置传参；自删除用 8.3 短路径；`--exes-only` 增量构建把迭代从 5 分钟压到 2 分钟。
- **法则**：安装器 UI 不依赖目标机器上不确定的东西（GUI 库/字体/系统对话框），浏览器 + 本地 HTTP 是最稳的兜底；目录选择给"内置选择器为主、系统对话框兜底"双通道。

### 12. 发布闭环与版本一致性

- **场景**：GitHub 附件用中文文件名被弄成乱码 `_._v1.0.exe`，删除后改 ASCII 名重传成功；应用内更新检查依赖 `APP_VERSION / VERSION 文件 / tag / Release` 四处一致。
- **发版 SOP（已写入 README）**：改 `app_update.py`（APP_VERSION/RELEASE_DATE/CHANGELOG）→ 同步根目录 `VERSION` → `git tag vX.Y.Z` → 创建 Release → 附件一律 ASCII 名。
- **法则**：版本号是数据不是记忆，所有引用点由同一份变更流程驱动；推送前必须 grep 密钥/令牌，敏感目录（config/space/data/output）进 `.gitignore`。

## 三、UX 工程的三个高杠杆技巧

1. **单变量控全站字号**：133 处 `font-size` 全部改 `calc(Npx * var(--fs))`，此后调字号只改一个变量（PC 1.22 / 平板 1.12 / 手机 1.06）。
2. **同一套 DOM + CSS 切换视图**：任务"卡片/列表"双视图不重写渲染逻辑，用 `display:contents` 让子元素直接参与 grid；轮询更新、id、按钮零改动，双视图天然同步。
3. **移动端优化先量化再动手**：390px 实测 `scrollWidth=632`（溢出 242px）定位到具体溢出元素再改；改完九档宽度逐一验证 `scrollWidth == clientWidth`。凭感觉调布局必然回归。

## 四、需求沟通的元经验

- **被用户纠正过的三处架构**（都值得写进团队规范）：模板中心单一数据源（第 6 条）；字幕切句规则两轮迭代（句号切分 → 停顿加权 → 逗号轻切分+淡入淡出）——"用户对成品的体感描述"背后是精确算法需求，要追问到可实现的定义；本地/在线用户判定（按访问来源回环判定，而非配置开关）。
- **先核对现状再动手**：每次大需求前先只读核查代码现状（如"改造前完全不是用户描述的逻辑"那轮），把差距列出来再实施，避免在错误地基上盖楼。
- **规则类文案不前置**：登录约定不写在登录界面，只在用户实际触发时给友好提示——预防性信息是噪音，触发性信息是帮助。

## 六、方法论总结（带走这一段就够了）

> 1. **动手前**：只读核对现状，列出"用户以为 vs 代码实际"的差距；
> 2. **写代码**：身份/归属/路径全部服务端裁决；读-改-写同一对象；状态机全分支覆盖；
> 3. **改完**：分清生效边界（静态刷新 / 重启）；控制台零报错 + 语法检查双闸；
> 4. **测试**：字节级快照 + finally 还原 + 零污染报告，用户数据神圣不可动；
> 5. **排障**：先最小复现推翻/证实假设，再动代码；
> 6. **对外依赖**：抖动默认可重试，长任务可重跑，失败原因透传到 UI；
> 7. **交付**：最大兼容面实现（浏览器 UI 兜底）、ASCII 文件名、版本四处一致、发版 SOP 固化进文档。
